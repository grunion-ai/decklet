## 0.11.0 — one save button, and it reads
- **"Save a copy" showed in every browser, and its tooltip lied.** `#savecopy{display:none}` is one id (1,0,0); `#hud button{display:inline-flex}`, later in the sheet, is an id and a tag (1,0,1) — so the button meant for the blocked-storage case was visible wherever storage worked, offering "this browser blocks storage, so edits only survive in a copy" to browsers that block nothing. Rather than patch the specificity, the door is folded into the one that already did the job: the save button's click runs `saveFile()`, which falls to `saveCopy()` when there is no file handle, so `#savecopy` is gone — markup, CSS and handler — and in the blocked state the save button's tooltip carries that sentence. ## 0.5.0 — the human's edits are the deck's
- **⌘S saves the file.** It downloaded a copy, so a deck on disk never held what its editor showed and an agent rebuilding it started from the model it last wrote. In Chrome/Edge the first ⌘S asks for the deck file once (File System Access, remembered per browser) and every save after — ⌘S and autosave alike — rewrites the file in place. Safari, and any browser without the API, still gets the download; on `file://` Safari also blocks storage, and the dot says so at load as before.
- **An edit log inside the file.** Every human mutation is diffed against the last save and appended to `/*LOG*/` as `{slide id, row id, key: [before, after]}` (row add/delete, slide add/delete/reorder and master edits included), stamped with the file rev it reached. The autosave dot is green only when the file carries everything; amber counts the edits that have not reached it. `bin/edits.mjs deck.html` prints the log for an agent.
- **`create --from prev.html`: the migrate step, last.** Regenerating a deck used to orphan every edit in the browser (the storage namespace was the model hash). Now `deck.id` is born once and kept, slide and row ids are inherited (by content, then by position), the human's log is replayed onto the new model — **human wins**; a key the agent changed too is a conflict, reported and kept on the entry with the agent's value — and the file's previous state goes into the version history. In the browser the same replay runs at load whenever the file's `rev` is newer than the stored working copy, so a rewrite neither hides the agent's changes nor drops the human's, and a stale copy can never mask a new file.
- **Versions, in the file.** `/*VERSIONS*/` keeps a snapshot per agent write, per ⌘S and per pin (cap 20). The history control lists them; Restore makes one the working deck after pinning the state you leave, so it is reversible.
- **Stable ids.** `deck.id`, `deck.rev`, `slide.id` (`s1…`), row `id` (`r1…`): deterministic, so the same model builds byte-identically; existing ids are kept. The validator accepts them.
- **Position by slide id.** A new window opens on slide 1. A refresh, and a new version of the file, keep the slide you were on — the tab remembers its slide by id, so an insert above does not move you. `#n` deep links still work.
- **Autosave that cannot lose a live edit.** A text edit in flight and a drag in progress are committed on `pagehide`/`visibilitychange`, so a refresh mid-sentence keeps the sentence.
- **Connectors get point nibs.** A `line` or `curve` showed the generic corner nib, sitting on a 3px shaft where every press hit it and dragged the stroke's size instead of the stroke. Now a selected connector shows one nib per endpoint (hollow ones on a curve's control points), each moving that point alone; a drag on the shaft (with a 6px halo) moves the connector whole. Dragging an end that `to:`/`from:` had clipped makes that end the human's.
- **A bound connector follows its target.** `to:`/`from:` clipped the stroke against the target's *current* box, but the model kept the point the author had aimed at. Move the box out from under that point — a drag, a nudge, a layout shift — and the clip found nothing inside, so the stroke sprang back to its authored length with the head floating where the box used to be, on a connector nobody had selected. A bound end whose aim point has left the box now re-aims at the box's centre before clipping, so the head tips on the box wherever it is; the model is untouched (following is a render-time reading), and an end the human drags off the box still becomes theirs. Live gate: the box travels 250×100 with nothing selected and the line, the bezier and a `from:` start all land 10px clear of the moved border.
- **Arrows survive the PDF.** The rasteriser treated any row containing an `svg` as media — which caught every arrow head — hid the row and redrew the svg alone, where `var(--accent)` and the rotation were gone, so the PDF had shafts without heads or no connector at all. Connectors stay in the styled layer; a live test reads the head's pixels back.
- **⌘B ⌘I ⌘U.** The toolbar had the marks; the keys did nothing. They mark a text selection while editing, and take the whole row when a text row is merely selected.

Press on empty canvas and drag and you pull a drag window that takes every row it **wholly contains** — containment, not touch, so a band pulled across a full-bleed backdrop takes the rows drawn on it and leaves the backdrop. ⇧ (or ⌘) adds to the standing selection instead of replacing it, under 4px is still a click and still deselects, and present mode is for reading: no band. Five of the seven rules carried that assumption, not the two that were spotted. The invariant is now explicit and applied once: **a connector is a stroke with a head**; a headless stroke is a rule, an underline, an annotation leader, a chart series or decoration, and none of the geometry rules apply to it. It is the same line the weight floor already drew (G1's 1.5px *with* a head was rejected and H5's 1px hairline leader accepted). Three thresholds were retuned against the probes at the same time, each of which had been flagging an accepted specimen: the no-air rule now means **touching** a border (`≤1px`) rather than merely tight, since that is what was ruled (K1 flush, D1 on it, D3/D4 inside) — a 2px gap is a weaker complaint that buried the real ones; the S-curve floor measures the connector's own span (88px) rather than the channel it sits in, so B5's 96px channel stops warning; and a **shared stub** now requires a segment that *feeds* the junction, which is what F3 and E4 have and F4 — two curves straight off one point — does not. Mapped over both probes, every remaining warning lands on a specimen that was rejected or called situational.
- **`dash` on `line` and `curve`, quantised to the run.** There was no dash prop; a `repeating-linear-gradient` on `bg` was the only way, and it cannot know the run length — so the last dash was always sliced mid-stroke (*"the dashes are not consistent and terminate part way through a dash"*) — and it silently ate the arrow head, because a gradient cannot fill a border colour. `dash:1` derives the pattern from the stroke weight, `dash:[on,off]` states it; either way the engine scales it so the stroke **begins and ends on a whole dash**, measured along arc length on a curve. The head is untouched.
- **Terminator shapes: `head:'triangle'|'chevron'|'dot'|'bar'`.** The engine had exactly one head, so a dot or a bar had to be mocked from extra rows and landed off centre. `arrow` says *which* ends carry a head, `head` says *what* is drawn there — one prop each, and one path per shape in a 0..10 box whose leading edge is x=10 and whose axis is y=5, so every terminator is centred on the stroke by construction. The same path feeds the line's inline SVG and the curve's marker, so the two painters cannot drift.
- **Connectors leave air.** `to:`/`from:` now back off `gap` (default **10**; `gap:0` is flush) instead of landing on the border — terminating *on* a border reads as touching, which is why it was rejected alongside terminating inside one.
- **`validate` enforces the connector shape rules** ruled on two probes: diagonal straight runs, S-curves in a channel under 96px, control points past the endpoints or under 40% of the run, a headed connector under 2.5px (a *headless* leader may be a hairline), no air at an end, uneven air between the two ends, and shared stubs. All **warnings**, never errors — a deck may have a deliberate exception, declared with **`waive:1`** on the row, the `over:1` of connector geometry. Each rule is scoped so it does not fire on things that are not connectors: a stroke under 40px is an icon (a tick, a cross), a tint band with no border is a backdrop rather than a container, a box holding *both* ends is the container the diagram lives in, and a shared vertex only counts as a stub between *headed* connectors (a chart polyline shares vertices by nature).
- **`verify` parity catches text over text** — a title landing on a caption, the third collision shape. Glyph rects again, `over:1` opts out. It caught a real one on rebuild: a probe slide whose title wrapped onto a specimen caption.
- The floating toolbar's link control is a flat `currentColor` SVG at the same optical size as **B I U S̶**, inheriting the toolbar's colour and its active state, instead of a coloured emoji raster.
- Tooltip/ARIA audit: every HUD control's `aria-label` now carries the same words as its tooltip, shortcut included; `⤒` says why it is there; the shortcuts popover names it. A new gate check reads every modifier chord the template actually handles and fails if one is missing from the popover, so the shortcuts list cannot drift from the keybindings the way the HUD contract did.
- **The arrow head is the terminus, not an appendage.** It was drawn *outside* the row's stated end — a CSS triangle at `right:-15px` on a `line`, and on a `curve` a marker anchored near its tip so the stroke ran to the very end and through the head. Every connector therefore rendered ~3.2x its stroke width longer than authored: on the connector probe a deliberately symmetric 8 px gap came out 8 px at the tail and **−7 px at the nose**, i.e. the head sitting inside the target. That single behaviour is what forced authors to hand-inset every endpoint. Now the stroke gives up exactly one head length at each headed end and the head fills that gap, tip on the stated point — measured on the probe, the room the stroke leaves for its head went **0 → one head length on all 29 specimens**, and every straight run went from 5–22 px inside its target to clear of it. `to:`/`from:` needs no adjustment: clipping the geometry to the border now puts the **tip** on the border. One `HEAD(sw)` sizes both painters, so the CSS triangle and the SVG marker can no longer disagree.
- The collision gate needed no threshold change for this class either. It measures the row's stated geometry, which was correct all along — the *renderer* disagreed with it. With the head as the terminus the model and the render describe the same shape, so the gate now sees what the eye sees (probe: A1 passes, a head aimed 20 px into a box fails).
- **Connectors terminate against a row, not at a hand-computed standoff.** `arrow:'end'` tipped exactly on the row's endpoint, so aiming a connector at the thing it points to — the natural authoring instinct — put the head ~20 px inside the target's fill, floating. `to:` and `from:` take a **row id** (on the slide or in the master) or a slide row index; the engine finds where the stroke crosses that row's box and clips it there, exactly, so the head tips ON the border. Straight lines are trimmed by interpolation, beziers by de Casteljau, so a clipped curve is still one exact cubic. Prefer an id: array indices shift the moment a row is inserted. This is what `curve`/`arrow` were supposed to finish — an author gives the target, never a standoff.
- **The page counter no longer emits an orphan separator.** A `footer:1` master row with no text of its own rendered `· 3 / 8`. The separator only means something after preceding text.
- **The HUD is a checked contract again.** It had drifted to eleven controls while `SKILL.md` still promised five. The manifest now lives in `SKILL.md` as a machine-read comment and the gate compares it against the template, so the HUD cannot gain or lose a control without the docs changing in the same commit. The peek HUD is also a **centred pill lifted off the bottom edge** — full-width at `bottom:0` put its right-hand controls exactly on the deck's own page counter whenever the canvas fills the screen, which a tall 4:5 deck always does.
- **The collision gate learns the two shapes it was missing.** It only ever checked ink over text glyphs, so it passed a deck with arrow heads sitting inside box fills and a label across a container's border. It now also fails:
  - **text straddling a container edge** — a label crossing a box/tile border, or hanging half out of the box meant to hold it. Measured on glyph rects: wholly inside or wholly outside, never across.
  - **an arrow head landing inside a fill** — the head endpoint deep inside a container the connector entered from outside. A box that holds *both* ends is the container the diagram lives in, not the thing being pointed at, and a headless stroke crossing a card is routing — neither fails.
  Both stay geometry-accurate rather than bounding-box: a tint with no border is a backdrop, a circle/pill outline is decoration whose bounding square is not an edge, and `over:1` opts a row out of all three checks.
- **Links survive, end to end.** One `href` model with two surfaces: a row prop (`href` on a painted CTA box *and* on its label row, painted as one inset anchor over the row — inert while editing, live in present mode) and an **inline link mark** in the floating toolbar, immediately after `S̶`, which wraps the selected run in `<a href>` exactly as `B` wraps it in `<b>`. The `.html` run allowlist grows `<a href>`. Both reach the `⤓` PDF as real `/Link` annotations with `/A << /S /URI >>` — which is what a LinkedIn document post follows — and both round-trip through `copy(JSON.stringify(deck))` → `create`. Scheme gate is `http`/`https`/`mailto`, applied in `validate` **and** again at render (a saved copy's model can be hand-edited).
- **`curve` and `arrow`.** `curve:[c1x,c1y,c2x,c2y,x2,y2]` is a cubic bezier connector — a row like `line`/`donut`/`bar`, absolute coords like `line`, drawn as one SVG path whose box wraps the whole control hull so parity can measure it. `arrow:'start'|'end'|'both'` puts a head on a `line` (a CSS triangle on the already-rotated row) or a `curve` (one `orient="auto-start-reverse"` marker). Flow diagrams stop being stiff diagonals, and nobody hand-builds an arrowhead out of three line rows and a trig helper again.
- **`verify` parity gains a collision check.** A leader line drawn straight through a text label used to pass every gate — the exact defect a human sees instantly. Parity now fails a painted row (background, border, line/curve/donut) that **crosses** a text row's glyph rects. Containment is not collision, so text on a tile, a label inside a box and a slide backdrop all pass; `over:1` on a row declares a deliberate overlay.
- **Blocked storage is diagnosed, not just red.** Safari refuses `localStorage` on `file://` — the way most people open a deck — so the autosave dot went red with no explanation and the hand-off promise ("edits persist per deck") was false. Availability is now **probed at load**: the deck adds `body.nostore`, says *why* in the autosave tooltip, and reveals a `⤒` **Save a copy** button next to `⤓` so `⌘S`, the only durable path there, is visible in exactly the state that needs it. The shim also keeps the session in memory, so navigation, the contact sheet and undo still work — only a refresh loses the edits. (There is no storage API that works from `file://` in Safari; indexedDB and cookies are blocked too.)
- **`⤓` no longer flashes an inverted slide.** The rasteriser used to drop each clone into document flow to serialise it and repaint the visible canvas to read a page colour. Every clone now lives in one offscreen host for its whole life, the page colour is read off the clone, and `⤓` carries `aria-busy` while it works. The output PDF is unchanged.
- Engine note: the deck's stylesheet is serialised verbatim into the PDF rasteriser's `foreignObject`, which is parsed as **XML** — a `<` anywhere in it, even inside a CSS comment, ends the export in a parse error.
- **`import-html --shots` actually writes the shots.** The flag was threaded all the way to `extract()` and then did nothing — `report.refs` came out `{}` on every run. Each page is now screenshotted at the model viewport **before** the walker touches the DOM (it materialises pseudo content and pins inline styles in place) to `<shots>/<page-basename>.png`, keyed by slide name in `report.refs` — exactly the filename `verify --refs` resolves.
- **`--title` no longer leaks its sentinels into the tab.** `put()` re-emits `/*MARK*/ … /*/MARK*/` so a built deck can be re-created; inside `<style>`/`<script>` that is a comment, inside `<title>` it was literal text, so the tab read `/*TITLE*/Q3 update/*/TITLE*/` and `⤓` downloaded `-TITLE-Q3 update-TITLE-.pdf`. **The deck now names itself:** `--title` wins, else the model's `title`, else `decklet`; the winner is written into the model (and into the namespace hash) and the runtime sets `document.title` from it. `<title>` in the template is plain static text and the TITLE marker is gone. One string is the tab title, the `⤓` PDF filename and the `⌘S` copy filename — and it round-trips through `copy(JSON.stringify(deck))` → `create` like any other model data.
- **`validate --style style.json`.** Text fit was measured against the model's own roles, falling back to the template's neutral scale — but the real scale usually arrives at `create --style`. `validate --strict` could report 0 warnings on a model that `create --style` immediately flooded with 14, three of them genuine `verify` parity failures. `validate` now takes the same `--style` and merges it through `mergeStyle()` — the one merge `create()` uses, exported from `bin/validate.mjs`, so the two scales can never drift.
- **Motion vocabulary.** `anim` grows from one word to four — `rise` (text), `fade` (quiet chrome), `pop` (stats, tiles, images), `wipe` (bars, lines, rules) — each a role-sized entrance, staggered 120 ms in model order on slide **entry** only. The renderer whitelists the four (an invented anim paints nothing and takes no stagger slot) and `validate` rejects anything else. One `prefers-reduced-motion` guard turns all of them off; print, the contact sheet, the `⤓` PDF and `verify` draw the settled frame, so motion cannot move what is measured or exported.
- **The explainer moves, and shows itself moving.** deck.html is now 12 slides: every headline enters, the chart wipes in, and two new slides — MOTION (the four anims demonstrated live, each tile arriving with its own caption) and THE EDITOR, FILMED (three inlined GIF clips: drag + multi-select, retype + the floating toolbar, contact-sheet reorder).
- **Filmed clips as a build product.** `docs/record-clips.mjs` drives deck.html with Playwright, films model-space crops of the real editor, encodes them with ffmpeg (48-colour palette, 10 fps, ≤ 3 s → 26–99 KB each) and writes the base64 back into `examples/explainer/model.json`. Re-run it, rebuild, and the clips are current — no screen capture in the loop. The deck stays one file with zero network at ~270 KB.
- README demo re-recorded on the 12-slide deck: it pages through slides that animate in, holds on the filmed clips and the MOTION slide, then reorders and writes a PDF (10 fps, 64-colour palette, no dither — 937 KB for 12.6 s).
- Gate: the residue grep ignores base64 payloads (a random three-letter run inside a clip is not residue).
- Contact sheet: `← Back` button top-left (aria-label "Back to slide (Esc)") closes to the current slide.
- Present mode (fullscreen) allows text editing: select text → the floating toolbar appears above the selection and pins the peek HUD; hidden when nothing is selected. The resize nib still never draws in present mode.
- Toolbar: inline segment is `B I U S̶` only (sub/superscript buttons removed — existing `<sub>`/`<sup>` runs still render, baseline shift only). Every segment is one centred line box (`inline-flex`), so the 16px colour swatches sit on the button axis. Palette stays **text colour only** — no box-fill.
- HUD: autosave dot moved immediately left of `+`; hover/title/aria-label carry status **and** last save time (`Autosaved · HH:MM:SS` / `Saving…` / `Not saved — edits will be lost on refresh (last saved …)`); green only after a confirmed `store.set`, red when the shim reports failure, re-probed on load. `ⓘ` shortcuts popover (rightmost; click/hover opens, click-away/Esc closes, pins the peek HUD) is the single home for hint text.
- `⌘S` / `Ctrl+S`: `preventDefault`, downloads a self-contained `.html` copy with the current model baked into the `DECK` literal and the storage namespace re-stamped — opens anywhere with the edits, no localStorage dependence. Keyboard-only.
- Position: the current slide persists through the shim (`<ns>:pos`) and mirrors into the URL hash (`#4`); an incoming hash wins on load, `hashchange` navigates, out-of-range clamps. Refresh lands on the same slide and `⌘Z` still restores (undo history was already persisted).
- Keyboard: `↑`/`↓` navigate like `←`/`→` (`↓` next, `↑` prev; Space kept); never while editing text or inside the contact sheet.
- HUD: `‹` / `›` nav buttons are icon-only (aria-label/title "Previous slide (←)" / "Next slide (→)"), matching `⤓ ⊞ ⛶`.
- Contact sheet: a pointer drag never runs native text selection alongside it — `user-select:none` on the sheet, cells and `body.dragging`; press and drag start `preventDefault()` and clear any selection.
- Autosave status dot beside `⤓`: green `✓` when the last mutation persisted through the storage shim, red when edits would be lost on refresh (shim reports storage unavailable / a save failed), amber pulse while saving; `store.set` now returns success; honours `prefers-reduced-motion`.
## 0.3.3 — the scale never crowds
- import-html **fit cap**: a role is its modal signature **capped by the tightest row wearing it**. The walker measures every boxed text row's `_fit` — the largest font-size at which it keeps its source line count inside its box — and `detectRoles` lowers the role to the smallest `_fit` below the modal (leading re-read from a real mockup signature at or below the cap). The scale may shrink a row, never crowd it; the cap is reported in `model.report.json` (`conflicts.<Role>.cap`). On a dense data deck this took Caption/Label 14 → 12 and removed every overflow and chip misalignment.
- verify parity is **hard again** for overflow and extra lines; a snapped row is tolerated only when it renders *fewer* lines than its source (collapsed inline runs), reported as crowding.
- import-html footer: a right-anchored hugging row matches the master by **either edge** (a footer whose text changes grows leftward; the left edge drifted 55px and the row was being hidden on one slide, leaving the generic pinned counter to collide with it). Typed page counts (`· 2/5`, `3 / 6`, `Page 2 of 5`) are stripped from the footer text before the vote — the engine renders the counter.
- import-html: a row whose first font family differs from its role's is a snapped row (`_src`), so the AE mask covers it.
- verify: the AE failure message names the pass column (after masks), not the raw diff.
## 0.3.2
- verify: AE pixel diff was a silent pass — `magick compare` exits 1 whenever the images differ and prints `AE (normalised)` on stderr; the parser read that as NaN → 0 → PASS on every deck. - verify: layout parity — a row the scale changed (`_src`, rendered as `data-snapped`) may wrap or crowd differently from its source; that is reported as **scale crowding** for a human decision, never a failure. Unchanged rows, `nowrap` rows and canvas bounds stay hard.
